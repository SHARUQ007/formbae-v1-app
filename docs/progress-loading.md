# Progress loading

Progress tab navigation uses an immediate transition so the selected page is not dependent on a fade animation completing. The existing dashboard, loading heading and retry state retain their layout.

The mobile `/progress` route now returns dashboard data with saved reports and forecasts. If analysis is due, it returns `generationPending: true` and schedules generation after sending the response. An existing report remains readable, including its original statistics. The first report stays pending until saved. Generation still uses the existing cadence, validation and repair rules.

Background work is deduplicated both inside each worker and across workers by an expiring Mongo lease in `progress_analysis_jobs`, keyed by user ID. Ownership is checked on release. A stopped worker's lease expires after 15 minutes; the next read can schedule another attempt. No report is force-regenerated by polling.

The app:

- Loads stats independently of pending body-measurement uploads.
- Uses a 30-second dashboard timeout instead of waiting seven minutes for AI work.
- Refreshes when Progress regains focus and polls every 15 seconds while analysis is pending, pausing off-screen and during a refresh.
- Keeps cached content visible on revalidation failure and ignores late results from superseded screen requests.

Validation: 316 app tests plus lint, TypeScript and asset checks; 183 backend tests. Regression cases cover pending analysis, preserved reports, deferred jobs, duplicate jobs and lease ownership, slow uploads, focus recovery, polling cleanup and overlapping requests. The simulator was signed out, so the reported intermittent native blank screen was not reproduced end to end.
